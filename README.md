
Code and reproducibility package for the paper:

**Benchmarking under Supplier Cold Start: A Layered Computational Market Approach to Data Asset Pricing**

## Overview

This repository contains the anonymized code and processed data required to reproduce the empirical analyses reported in the revised manuscript.

The current reproduction pipeline is consolidated into a single standalone Python program:

```text
run_paper_all_from_raw_standalone_with_excel.py
```

The program follows the same sequence as the manuscript's empirical analysis:

1. data validation and descriptive market evidence;
2. global benchmark evaluation under ordinary and supplier-held-out validation;
3. local comparable retrieval and cold-start recovery;
4. Bayesian reconciliation and predictive-uncertainty reporting;
5. representation and architecture ablations;
6. supplier-topology diagnostics, paired-bootstrap inference, and graph-embedding sensitivity;
7. manuscript-ordered final tables, figures, and reproducibility exports.

The primary specification is executed once. Fold-specific graph embeddings, text representations, model tuning, comparable libraries, and uncertainty parameters are learned using training-fold information only.

## Main program

### `run_paper_all_from_raw_standalone_with_excel.py`

This is the complete end-to-end reproduction program for the revised empirical analysis. It does not import or call any other project-specific Python file.

The program performs six execution phases (Phase 0 through Phase 5):

### Phase 0 — Input validation and modeling-sample construction

The program validates and aligns the two frozen reproduction inputs.

- The anonymized Excel file is the authoritative source for:
  - `price` (USD per call),
  - `price_CNY` (original CNY per call),
  - `name`,
  - `desc`,
  - supplier and ontology-category fields used for consistency checks.
- `api_data_snapshot.csv` is the authoritative portable snapshot for:
  - product node identifier (`pid`),
  - historical row order,
  - source-industry memberships (`src_list`),
  - application-domain memberships (`app_list`).

The KG snapshot is **not** a precomputed graph-embedding table. Graph embeddings are re-estimated within each outer training fold.

The program also checks that:

- the Excel and KG snapshot contain the same product set;
- product names are unique and aligned;
- supplier identifiers and descriptions agree across the two inputs;
- ontology memberships agree across the two inputs;
- USD and CNY prices are internally consistent at **1 USD = 7.1429 CNY**;
- the final analytical input already satisfies the positive-price and upper-tail screening rules.

The revised Excel file already stores the model-facing price in USD per call. The program validates the currency relation but does **not** convert the USD price a second time.

### Phase 1 — Descriptive market evidence

This phase reproduces:

- manuscript Table 1;
- Appendix Table A1;
- Appendix Fig. A1;
- Appendix Fig. A2;
- sample and supplier-level audit outputs.

The descriptive evidence covers the posted-quote distribution and supplier-level clustering used to characterize supplier anchoring.

### Phase 2 — Main empirical evidence

The main LCMA pipeline is evaluated under:

- five-fold random **KFold** validation; and
- five-fold supplier-grouped **GroupKFold** validation, where test suppliers are entirely absent from training.

The program evaluates:

- Global Ridge prior benchmark;
- KNN Mean;
- KNN GapTrim;
- Bayes Mean;
- Bayes GapTrim;
- Plus Bayes (robust-variance extension);
- Stacking Conformal.

This phase produces the main benchmark-performance results, out-of-fold predictions, Bayesian-reconciliation diagnostics, Appendix C mechanism diagnostics, and Appendix E uncertainty-calibration results.

All fold-dependent representation learning, tuning, comparable retrieval, and uncertainty estimation are restricted to the corresponding training fold.

### Phase 3 — Representation and architecture validation

This phase decomposes the empirical contribution of the LCMA components.

**Representation ablation**

- Text only
- KG only
- KG + Text

**Architecture ablation**

- Global Ridge
- Local KNN
- non-Bayesian global-local fusion
- Bayesian reconciliation

The phase also runs a matched-seed supplier-topology diagnostic that compares the full relational representation with supplier-neutral graph variants.

These outputs provide the basis for manuscript Table 3 and the corresponding Appendix D diagnostics.

### Phase 4 — Statistical robustness and sensitivity

The robustness stage adds:

- paired-bootstrap inference for representation contrasts;
- paired-bootstrap inference for architecture contrasts;
- paired-bootstrap inference for supplier-topology contrasts;
- matched-seed graph-embedding sensitivity;
- graph-embedding dimension sensitivity at dimensions 16, 32, and 64.

The default full analysis uses **5,000 paired-bootstrap replications** and **three matched graph-validation seeds per fold**.

### Phase 5 — Manuscript-ordered exports

The final phase exports the empirical results in manuscript order and creates a complete reproducibility workbook.

The final workbook is:

```text
paper_result_final/paper_results_tables/All_Tables_Main_and_Apppendix.xlsx
```

It contains the following tables in order:

1. Table 1 — Distribution of posted quotes
2. Table 2 — Main benchmark performance
3. Table 3 — LCMA ablation
4. Appendix Table A1 — Supplier-level clustering
5. Appendix Table B1 — Gaussian working-approximation diagnostics
6. Appendix Table C1 — Shrinkage diagnostics
7. Appendix Table C2 — Tail-risk diagnostics
8. Appendix Table C3 — High-disagreement subset diagnostics
9. Appendix Table C4 — Decile-based gain patterns
10. Appendix Table D1 — Representation ablation
11. Appendix Table D2 — Architecture ablation
12. Appendix Table D3 — Training-fold calibration of non-Bayesian fusion
13. Appendix Table D4 — Paired-bootstrap inference for representation contrasts
14. Appendix Table D5 — Paired-bootstrap inference for architecture contrasts
15. Appendix Table D6 — Matched-seed supplier-topology results
16. Appendix Table D7 — Paired-bootstrap inference for supplier-topology transfer
17. Appendix Table D8 — Graph-embedding dimension sensitivity
18. Appendix Table E1 — Predictive-uncertainty robustness and interval calibration

A standalone CSV is also exported for each official manuscript table.

## How to run

From the repository root:

Main dependencies include:

- numpy
- pandas
- matplotlib
- scipy
- scikit-learn
- networkx
- gensim
- openpyxl

Install dependencies with your preferred environment manager (for example, `pip`, `conda`, or `venv`).

### Run the main paper pipeline
```bash
python run_paper_all_from_raw_standalone_with_excel.py
```

With the default repository structure, no command-line arguments are required.

The default inputs are:

```text
price_files/dataproduct_industry_analysis_list_format_anymous.xlsx
export_neo4j/api_data_snapshot.csv
```

and the default output root is:

```text
paper_result_final/
```

### Custom input or output paths

```bash
python run_paper_all_from_raw_standalone_with_excel.py \
  --input-excel /path/to/dataproduct_industry_analysis_list_format_anymous.xlsx \
  --kg-snapshot /path/to/api_data_snapshot.csv \
  --output-root /path/to/output_directory
```

### Smoke test

For a quick code-path check, the first `N` folds of each validation protocol can be run with:

```bash
python run_paper_all_from_raw_standalone_with_excel.py --max-folds 1
```

This is only a smoke test and does **not** reproduce the full manuscript results.

### Bootstrap replications

The full manuscript specification uses 5,000 paired-bootstrap replications:

```bash
python run_paper_all_from_raw_standalone_with_excel.py --bootstrap-B 5000
```

A smaller value may be used for testing, but it will not reproduce the reported bootstrap results.

### Graph-validation repeats

The default matched-seed topology and dimension analyses use three graph-validation repeats per fold:

```bash
python run_paper_all_from_raw_standalone_with_excel.py --graph-validation-repeats 3
```

### Skip graph-dimension sensitivity

For development or smoke testing only:

```bash
python run_paper_all_from_raw_standalone_with_excel.py --skip-dimension-sensitivity
```

Skipping this stage will omit the complete graph-embedding dimension-sensitivity evidence reported in Appendix D.

## Reproducibility safeguards

The program includes several safeguards designed to prevent accidental data leakage or input inconsistency:

- KFold results are always generated before GroupKFold results.
- In GroupKFold, train and test supplier sets must be disjoint.
- Test rows never enter graph-embedding or text-representation fitting.
- Hyperparameter tuning and comparable-library construction use training-fold information only.
- The Excel and KG snapshot are cross-validated before modeling.
- The KG snapshot preserves relations and row order but not precomputed embeddings.
- Common fold-specific seeds are used in auxiliary graph comparisons so topology or dimension changes are not confounded with arbitrary seed changes.
- The final workbook and standalone tables are exported in manuscript order.

The weighted random-walk implementation also precomputes transition structures once per graph. For a fixed seed, this preserves the intended walk sequence while substantially reducing graph-embedding runtime.

## Reproducibility scope and data release

This repository is a paper-level reproducibility package. It provides the complete current empirical program, anonymized processed inputs, and generated outputs needed to reproduce the revised manuscript analyses.

It does **not** release the original raw scraping pipeline, original marketplace identifiers, or unprocessed platform records.

The released files are anonymized because the original marketplace materials may contain supplier- and product-level information that could facilitate re-identification or reverse mapping to original entities. The reproduction package is therefore designed to preserve the empirical structure required for replication while avoiding unnecessary disclosure of source-level identifiers and commercially sensitive details.

The repository should not be interpreted as releasing complete original marketplace data.
